# 第一次使用：一步一步打开破局

## 1. 下载正确的文件

1. 登录有此私有仓库访问权限的 GitHub 账号。
2. 打开仓库右侧的 Releases，进入 `v2.1.1`。
3. 在 Assets 中下载 `Poju-Deploy-v2.1.1.zip`。
4. 若只想使用，选择部署包；GitHub 自动生成的 Source code 压缩包主要用于开发。
5. 将 ZIP 保存到电脑，例如下载文件夹。

私有仓库链接只有有权限的人才能访问。若要把程序发给队员，可下载部署 ZIP 后单独发送；不要把自己的 `data` 文件夹一起发出去。

## 2. 完整解压

1. 右键 ZIP →“全部解压”，选择固定目录，例如 `C:\Poju`。
2. 打开解压目录，确认能看到 `server.mjs`、`public`、`lib`、`server` 和启动文件。
3. 不要在压缩包预览窗口中直接启动，也不要只复制一个 HTML 文件。

## 3. 安装运行环境

1. 打开 [Node.js 官方下载页](https://nodejs.org/en/download)，安装 24 系列对应操作系统的版本。
2. 完成后重新打开 PowerShell 或命令提示符。
3. 输入 `node --version`。应出现 `v24.x.x`；本版本验证使用 24.19.0。
4. 如果出现“不是内部或外部命令”，重新打开终端，或检查安装时是否添加了 PATH。

## 4. 启动并打开网页

Windows：双击 `启动-本机预览.cmd`。保留窗口，在浏览器输入：

```text
http://localhost:8080
```

其他系统：在解压目录打开终端，运行 `node server.mjs`，再打开同一地址。

页面需要后台程序运行。`file:///C:/code/` 是本地文件路径，无法代替后台地址；直接打开 `public/index.html` 也不能登录或保存进度。

## 5. 第一次负责人登录

1. 等待启动窗口显示“破局训练场已启动”。
2. 打开程序目录的 `data/owner-code.txt`。这是首次启动生成的专属负责人码。
3. 在网页切换到“负责人登录”，粘贴完整码。
4. 登录后进入团队看板，点击“生成快捷码”。
5. 保存网页显示的 12 位快捷码。快捷码只显示一次，原负责人码仍可使用。
6. 为自己另建成员账号可体验普通成员视角；负责人也能在训练大厅开局。

本地首次启动没有预设公共口令。不要把负责人码贴在群里或提交 GitHub。

## 6. 下一次继续

再次启动同一文件夹中的启动程序，访问同一地址。程序会读取 `data` 中原有数据，不必重新添加成员。关闭网页不会清除已保存草稿；未完成一局可在训练大厅点“继续训练”。

停止时，在启动窗口按 `Ctrl+C`，等待退出。不要在运行中移动数据文件夹。

## 7. 手机和其他电脑怎样使用

**每个人独立使用：**给每人发送干净部署 ZIP，每个人启动自己的副本。数据分别保存在各自电脑，负责人无法自动汇总，可截图汇报。

**共用一个团队后台：**由负责人在一台电脑或服务器运行同一份程序，所有人访问它的 HTTP/HTTPS 地址。手机只需浏览器，不必安装 Node。负责人电脑必须保持开机，网络可达。手机不能直接使用 Windows 启动文件。

同一 Wi-Fi 下临时测试，可在 PowerShell 中运行以下命令（将示例地址换成该电脑实际的局域网 IPv4 地址）：

```powershell
$env:HOST='0.0.0.0'
$env:PORT='8080'
$env:APP_ORIGIN='http://192.168.1.20:8080'
node server.mjs
```

电脑和手机都使用这里设置的同一地址。Windows 防火墙如提示，按实际网络选择允许访问。此方式使用 HTTP，只适合可信局域网临时测试；跨网络正式共享按[部署说明](deployment.md)配置 HTTPS。更换地址后必须重启程序，并在浏览器使用与 `APP_ORIGIN` 完全一致的地址。

## 8. 打不开时逐项检查

| 现象 | 处理方法 |
| --- | --- |
| 浏览器显示无法访问文件 | 输入 `http://localhost:8080`，不要输入文件夹路径 |
| 网页连接被拒绝 | 确认启动窗口仍在运行；先查看窗口报错 |
| 提示 Node.js 未安装 | 安装 Node 24，重新打开终端或启动文件 |
| `EADDRINUSE` | 8080 已被占用；先关闭自己先前启动的破局，或按开发说明换端口 |
| 提示请求来源不匹配 | 浏览器地址必须与 `APP_ORIGIN` 一致，包括协议、主机和端口 |
| 负责人快捷码忘记了 | 使用原 `data/owner-code.txt` 登录；不要删除数据库 |
| 刷新后似乎没有以前记录 | 确认启动的是原文件夹，且 `DATA_DIR` 没有变 |
| 成员不能进团队后台 | 需要负责人码，普通成员码没有查看全队数据的权限 |

升级、迁移前请先做[数据备份](deployment.md)。
