# 模型、数据和验证范围

## 模型与解释

模型主要在 lib/engine.mjs，初始资金 650 万，共 25 家公司、八季度。市场情景、种子、筹备方案和每季决策构成可重放状态。engine-v1.mjs 保留旧记录兼容能力。

24 个模拟对手由八类策略与不同参数组合驱动。高难度调整判断与规划，仍使用相同资金和经营规则。它们不是大语言模型实时调用，也不代表经过实测认证的真人参赛队伍。1–10 级只是内部难度刻度。

策略识别读取实际经营数据，给出行为标签与数字证据；不能据此断言对手的主观想法。单项回测固定已发生市场和其他公司的同季选择，只衡量该条件下结果变化。未来市场、对手反应和长期投资回收需要另行判断。

企业案例在 lib/cases.mjs 保存来源、核对日期、公开事实、教学迁移和限制。资料日期沿用原版，发布到 GitHub 不表示已重新核对全部最新财报。案例不是企业生产系统的数字孪生。

## 数据保存

- SQLite 保存成员、登录会话哈希、活动心跳、局面、草稿与事件。
- 首次运行生成负责人码；成员码和会话令牌在数据库中以哈希保存。
- HTTP 接口 /api/platform，通过 HttpOnly Cookie 传递身份。
- 修改请求检查来源；负责人操作在服务端验证角色。
- 季度提交使用版本号和命令标识，避免重复结算或旧窗口覆盖。
- 负责人可读成员复盘信息；普通成员不能读取团队后台。

## 自动验证

运行 npm test，包含：

1. 模型与教学：11 项字段完整性、固定条件回测与实际模型一致、旧版记录、投资生效时间、末季资源、25 公司当季排名、并列与无当季记录、名次变化。
2. 独立 API：新库初始化、登录、成员码、来源、权限、难度范围、幂等提交、旧版本冲突、完整八季、团队记录、计时租约与案例反馈。
3. 构建打包：Vite 可独立构建网页；部署包按清单生成，不读取实际业务数据目录。

API 测试使用系统临时目录启动独立本机服务，结束后只清理自己的测试目录，不访问现有在线平台。

这些测试验证模型一致性和指定接口流程，不验证官方比赛相似度、真人水平、长期生产负载或所有浏览器兼容性。页面沿用已有中文界面，发布时另做浏览器抽查。
